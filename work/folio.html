Folio

A journal meant to feel like opening a hardbound book—3D cover, drag-to-fold page curls, a pullable bookmark ribbon—where you can type, sketch with pressure-sensitive ink, or dictate. Guest mode keeps everything on-device; Google Sign-In syncs prose, drawings, and spreads across phones and tablets.

React 19, TypeScript, Vite, Tailwind CSS, GSAP, Express, Firebase Auth & Firestore, Groq Whisper, Google GenAI · GitHub · live app

Problem

Most notes apps look like dashboards. I wanted a journal that rewards slowing down: a hardbound cover you open, spreads you turn by dragging a corner, and paper you can switch between ruled, dotted, or blank—with prose ink, a font picker, and a stylus layer when you want to sketch margins instead of type.

That surface has to coexist with real product plumbing. Entries should work offline as a guest, merge cleanly when you sign in with Google and pick up on another device, export to CSV for backup, and support fast voice dictation without exposing API keys in the browser or letting one user burn through transcription quota.

Book UX

PageCurlStage drives the experience: book phases (closed → opening → open), GSAP timelines for the cover and cast shadows, spine-clamped geometry from pageCurlGeometry.ts, and a bookmark ribbon with pull resistance and spring bounce. Desktop shows two-page spreads; portrait mobile uses a single page with a landscape nudge.

Each spread holds typed bodies, serialized stylus strokes per page (leftInk / rightInk), paper style, ink color, and an optional context note. Welcome content explains guest vs cross-device sync; the closed cover shows the journal date before you open.

Drawing and input

An ink canvas sits above the ruled sheet: pen, fountain pen, and highlighter with pressure-aware width, stroke and barrel erasers, undo/redo, and a toolbar for brush color and weight. Apple Pencil, touch, and mouse are distinguished via pointer types; palm rejection keeps stylus strokes from triggering page curls unless you explicitly enable finger drawing.

Overflow prose flows onto the next page or continuation spread when a side fills up, so long entries do not fight the fixed sheet height. High-frequency ink and curl updates run through refs where possible so the book does not re-render at 60fps.

In the browser

State and sync

useJournalStore and useJournalSync keep spreads in a reducer—bodies, ink payloads, navigation, overflow continuations—and reconcile with Firestore via snapshots, batched uploads, and debounced writes when signed in. UI surfaces syncing / synced / error with retry; guest arrays in localStorage merge into the cloud profile on first sign-in without dropping in-progress text or strokes.

Ink canvas

useInkCanvas renders DPR-aware strokes from compact serialized ink on each spread side; useInkWorkspace owns toolbar state, touch-draw toggle, and undo stacks. Drawing arms only when the toolbar is open (except Apple Pencil paths), and page curl ignores touch while stylus drawing is active.

Firestore rules

Owner-only reads and writes on /users/{userId} and nested spreads—field length caps and immutable userId on each spread match firestore.rules and the blueprint JSON in the repo.

Voice pipeline

useVoiceRecorder shows a live level meter, applies client-side silence gating, and uploads compressed audio by default (mono WAV boost when the mic is quiet). The client sends a Firebase bearer token; server.ts verifies Google certs, enforces per-IP and per-user rate limits, daily audio budgets, payload and WAV duration checks, then calls Groq whisper-large-v3-turbo with Gemini fallback. Structured logs record outcome and duration—never raw audio or transcript text.

Ship path

Production is a single node:22-slim container: npm run build for the SPA, node server.ts on port 8080 serving static assets and API routes—deployed today as the Google AI Studio live app linked above.

Proof

Open the live journal

The hosted build matches GitHub at v1.1.0: open the cover, sketch or type on a spread, flip pages with the curl or ribbon, and—when signed in—see entries sync across devices while dictation runs through the guarded API. Voice requires Google Sign-In for quotas; guests still get writing, drawing, styling, and CSV export locally.

No synthetic engagement metrics on this page—the proof is the interactive book, ink layer, and the transcription guardrails documented in the repo README.

What I’d change next

  • Back rate limits and daily quotas with Redis or Firestore when running multiple Cloud Run instances—today counters are in-process.
  • Add collaborative or shared journals only if privacy rules can stay strict; current schema is single-owner by design.
  • Capture a short screen recording of a page turn for the repo README; portfolio gallery uses static PNGs at full resolution.
  • Broaden automated tests around merge-on-sign-in, ink round-trips, and conflict ordering via <code>clientUpdatedAt</code>.
