Folio

A journaling app meant to feel like opening a notebook—closed cover, drag-to-turn spreads, ruled or dotted paper—while still handling sync, export, and server-side voice transcription with real quotas and auth.

React 19, TypeScript, Vite, Tailwind CSS, GSAP, Express, Firebase Auth & Firestore, Google GenAI · GitHub · live app

Problem

Most notes apps look like dashboards. I wanted a journal that rewards slowing down: a cover you click open, spreads you turn by dragging a corner, and paper you can switch between ruled, dotted, or blank—with ink that still feels like ink.

That surface has to coexist with real product plumbing. Entries should work offline as a guest, merge cleanly when you sign in with Google, export to CSV for backup, and support voice dictation without leaving the API key in the browser or letting one user burn through Gemini quota.

Book UX

PageCurlStage drives the experience: book phases (closed → opening → open), GSAP timelines for the cover, and geometry from pageCurlGeometry.ts so drags and corner hovers fold a page believably on desktop spreads or a single mobile page.

Each spread holds left and right bodies, a date line, optional context note, and per-spread paperStyle and inkColor. Welcome content explains guest vs signed-in sync; the closed cover shows the current journal date before you open.

In the browser

State and sync

useJournalStore keeps spreads in a reducer: update bodies, turn pages, create/delete spreads, and reconcile with Firestore via real-time listeners when signed in. Guest arrays in localStorage merge into the cloud profile on first successful sign-in without dropping in-progress text.

Firestore rules

Owner-only reads and writes on /users/{userId} and nested spreads—field length caps and immutable userId on each spread match firestore.rules and the blueprint JSON in the repo.

Voice pipeline

useVoiceRecorder captures mono 16 kHz WAV in the browser. The client attaches a Firebase bearer token; server.ts verifies Google certs, enforces per-IP and per-user rate limits, daily audio budgets, WAV magic-byte and duration checks, then calls Gemini. Structured logs record outcome and duration—never raw audio or transcript text.

Ship path

Production is a single node:22-slim container: npm run build for the SPA, node server.ts on port 8080 serving static assets and API routes—deployed today as the Google AI Studio live app linked above.

Proof

Open the live journal

The hosted build is the same tree as GitHub: open the cover, write on a spread, flip pages, and (when signed in) dictate into the page. Voice requires Google Sign-In so per-user quotas can apply; guests still get full writing, styling, and CSV export locally.

No synthetic engagement metrics on this page—the product proof is the interactive book UI and the documented transcription guardrails in the README.

What I’d change next

  • Back rate limits and daily quotas with Redis or Firestore when running multiple Cloud Run instances—today counters are in-process.
  • Add collaborative or shared journals only if privacy rules can stay strict; current schema is single-owner by design.
  • Capture a short screen recording of a page turn for the repo README; portfolio shots above are static PNGs at full resolution.
  • Broaden automated tests around merge-on-sign-in and conflict ordering via <code>clientUpdatedAt</code>.
