FocusFleet

Live-camera fatigue detection for drivers: fast geometry on every frame, a small model for confirmation, and alerts only when drowsiness persists.

Python, OpenCV, MediaPipe Face Mesh, TensorFlow/Keras, CustomTkinter, Gradio, SQLite

Problem

Fatigue from a live camera needs to be caught in real time. False alarms erode trust; missed drowsiness is unsafe. The pipeline has to hold roughly 30 frames per second, drive audible alerts, and keep session history for later review—on desktop and in the browser.

The same detection core powers a CustomTkinter desktop app and a Gradio web app deployed to Hugging Face Spaces, with driver auth and SQLite session logging on both paths.

Geometry first, model second
EAR and MAR from MediaPipe Face Mesh keep latency low at 30 fps. The TensorFlow/Keras model is secondary validation before declaring drowsy—speed on the hot path, accuracy when it matters.
State machine, not per-frame alerts
States move ACTIVE → WARNING → DROWSY → FACE_LOST. Thresholds must breach persistently before audio fires, so normal blinks do not spam the driver.
Event-driven logging
logger.py writes session data on state transitions, not on every frame. SQLite stays useful on long drives without I/O choking the loop.

Proof

96% test accuracy · 30 fps

96% is the held-out test-set accuracy from training—not a field trial on every road condition. The pipeline targets 30 fps processing on a live stream; the Gradio build is deployed on Hugging Face for a browser demo.

What I’d change next

  • The Keras artifact is about 797 MB—too heavy for edge or mobile without quantization, a smaller model, or ONNX/CoreML export.
  • Deduplicate engine.py and logger.py across application/ and web/ into one package with thin UI shells.
  • Per-driver calibration of EAR/MAR thresholds and more hard negatives (glasses, low light).
  • Track p95 milliseconds per frame in CI, not only offline accuracy.
