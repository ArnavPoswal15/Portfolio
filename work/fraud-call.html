Fraud Call Detection

Scam-call classification on IBM Watson transcripts: normalize utterances, score with fine-tuned XLNet, and report accuracy on a held-out recording set—not live telephony or in-call blocking.

Python, IBM Watson Speech to Text, XLNet (xlnet-base-cased), scikit-learn, Google Colab · GitHub · Hugging Face weights

Context

This was my B.Tech minor project in the 7th semester: build a pipeline that reads call transcripts and labels them fraud or not fraud. The goal was to learn speech-to-text integration, text normalization, and transformer fine-tuning—not to ship real-time call blocking.

Evaluation uses pre-transcribed JSON from IBM Watson on a fixed set of recordings. You can rerun the notebook on Colab without retraining—the checkpoint downloads from Hugging Face.

Problem

Scam calls reuse themes—tax debt, account suspension, urgent wire transfers—but the exact wording changes every week. Keyword lists miss paraphrases and polite framing.

The model needs context from full utterances after normalization: contractions expanded, stopwords trimmed, lemmas aligned with the training vocabulary in NLP_txt/.

Pipeline

Audio (or existing Watson JSON in SpeechToText/json/) flows through IBM Watson Speech to Text with speaker labels. The notebook normalizes each transcript, then runs a two-class XLNet head fine-tuned from xlnet-base-cased.

Training mixes scraped scam-related tweets (fraud class) with Santa Barbara Corpus conversation excerpts (normal class)—see the repo README for how Dataset.csv is built. Ground truth for the 21 test recordings follows a simple filename rule: names containing - (e.g. irs_tax-fraud.json) are fraud; SBC*.json files are normal.

Evaluation

Speech to text and labels

IBM Watson Speech to Text produces JSON with speaker-labeled segments. For evaluation, fraud vs normal is inferred from filenames: *-fraud.json vs SBC*.json, matching the notebook’s scoring rule.

Text normalization

The pipeline lowercases, strips punctuation, expands contractions, removes stopwords, and lemmatizes using word lists under NLP_txt/ so inference text matches training preprocessing.

Model and hosting

Fine-tuned weights live on Hugging Face (ArnavPoswal15/xlnet-fraud-call). Colab downloads them by default; set RETRAIN = True in the notebook to fine-tune again on Dataset.csv (GPU recommended).

Proof

20/21 · 95.2% accurate

On 21 test recordings (10 fraud, 11 normal), the model classified 20 correctly. All 10 fraud calls were caught; one normal call (SBC047) was flagged as fraud—matching the README and the table above.

The held-out set is small—one recording shifts accuracy by about 5%. Fraud training text came from tweets and normal text from conversation transcripts, so performance on other call types may differ. Fraud test transcripts tend to be shorter than normal ones.

What I’d change next

  • Grow a larger held-out set with in-domain fraud audio transcripts, not only tweet-derived training text.
  • Report confidence thresholds and calibration, not only argmax labels on 21 files.
  • Avoid publishing raw third-party corpus text on a marketing page—link to the repo and Colab instead.
  • Seed training runs or document variance when <code>RETRAIN</code> is enabled—the notebook notes unseeded runs drift slightly.
